v2 writes NTFS well enough to be used.

Files can be made, filled, cut down, overwritten, renamed, moved between
directories and taken away. Folders can be made, filled, emptied and removed.
A directory that outgrows its record grows blocks of its own, a full node
splits, and a full root gives the tree another level.

Speed, against APFS on the same machine: a file is created in 74 microseconds
against 64, and removed in 56 against 48. Writing a megabyte at a time reaches
8.6 GB/s where the same writes with no filesystem under them reach 14.7 -- both
of those are page cache, and either is far past any drive this will ever run on.
Listing a directory is one pass and then 0.8 microseconds a page, whatever its
size.

There is still no journal, and there is not going to be one: no NTFS
implementation outside Microsoft has one. The volume carries the dirty flag
while it is held, in both copies of $Volume, and every operation is ordered so
that an interruption leaves space to reclaim rather than a name pointing at
something that is not a file. The flag comes off when the mount ends.

Reading the code that faces macOS, rather than the code that reads disks, found
seven defects that no test here would ever have caught -- a mount that never
came clean, a rename that destroyed what it was replacing, a truncate that did
nothing, a leak of one file's bytes into another, sizes and times that a listing
would have shown as zero, and a directory listing whose cost grew with the
square of its size. A reader and a writer that share an assumption agree with
each other perfectly, which is why there is now an independent checker written
from the on-disk format in another language, and why it is itself checked
against deliberate damage.

This branch releases nothing. It is v2's development line, and release.sh
refuses to publish from it.
