- An empty lost+found is not left on somebody's NTFS volume.
- Every entry on a served drive is readable and writable, whatever mode or flag the disk stores.
- The guest grants every access a read-only mount does not refuse, whatever user the server acts as.
- inode_permission keeps no unused variable.
- A read-only btrfs snapshot still refuses, and an open drive no longer stops another from opening after an update.
- The guest copy of vmproxy is settled to the nanosecond, the check never mounts a drive an engine still holds, and a second drive is proven on real drives.
- The helper stops an engine mount left serving nothing, which otherwise holds the lock and the drive.
- An idle engine mount is found by the host the engine really names, so LVM, RAID and renamed shares are never stopped.
- Nothing is stopped while any engine share is served from an address instead of a name.
- Nothing is stopped while any NFS share is served from an address, on vmnet and IPv6 as well as loopback.
- Tests that write fixed names under the shared temporary root name them per run, so two runs cannot delete each other's stubs.
- An engine is stopped only on a process list and a mount table that were both read to the end.
- A program's output is drained while it runs, so a long output finishes inside its deadline instead of reading as silence.
- A program is read through handlers, so one that outlives its deadline leaves no thread waiting behind it.
- A USB drive macOS reads as APFS is not listed.
- The APFS container is found from the partition's own info, which the list of physical disks leaves out, and only the whole disk is withheld.
- The scan hands the leftover pass a lookup a test can call, so the APFS answer it depends on is checked.
- An open drive is in Finder's sidebar under Favourites, and leaves it when the drive closes.
