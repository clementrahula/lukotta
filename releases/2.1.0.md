v2 reads NTFS, and now writes it.

A filesystem extension that serves a volume from a process rather than the
kernel, with its own NTFS implementation underneath: the master file table,
records and their fixups, attributes, runlists, directory B-trees, the cluster
and record bitmaps, timestamps, and AES-XTS so an encrypted drive reads as
though it were not.

Files can be made and taken away. A create claims a record, composes it, and
files the name where the volume's own `$UpCase` table says it belongs; a remove
takes the name out, frees the record, and leaves everything else where it lies
so the file can still be recovered. Directories grow: a full node splits, and a
full root gives the tree another level.

There is no journal, and there is not going to be one -- no NTFS implementation
outside Microsoft has one. Instead the volume carries the dirty flag while it is
held, in both copies of `$Volume`, and every operation is ordered so that an
interruption leaves space to reclaim rather than a name pointing at something
that is not a file. A volume whose own journal has unfinished work in it is
refused for writing and still read.

Measured against a copy of a real drive: 78 microseconds to create a file and 60
to remove one, where APFS on the same machine takes 64 and 48.

This branch releases nothing. It is v2's development line, and `release.sh`
refuses to publish from it.
